# 天才课堂 · 质量控制方案（中文稿，供审阅）

内容电脑（Claude）起草，2026-11-21；请 TTS 电脑审阅（gladcolor/gc-audio-science 第 13 号 issue），由用户批准。英文版见 `tools/QC-PLAN.md`，两稿内容一致，以本稿为准时同步修改英文稿。

**原则：质量第一。** 一页课文或一课录音算“完成”，只能由下面的检查结果说了算，绝不靠数自己做了多少。用户发现的每一个问题，都要变成一条规则和一项自动检查，不让它再出现。
**一课一课来**（用户，2026-11-21）：录音和检查都按课进行，一课做完、查完、确认后，再做下一课；不再做全站批量。汇报时报“完整了几课”，不报录音条数。

分工：**CP** 内容电脑（Claude）· **CX** Codex（撰写／审查）· **TP** TTS 电脑 · **U** 用户。
检查方式：**A** 自动脚本 · **L** LLM 审查（另一次独立的审查）· **H** 人工（听、看）。

## 1. 课程
- 标准：每个课题对应一项课程标准（佐治亚州 GSE 6–8 年级，和／或人教版、统编版 7–9 年级），否则标为“课外拓展”；对照两套课程，目录中没有缺口；进阶模式与标准核心内容分开。
- 检查：A 目录与课标清单的对照表（school-topics/、目录中的 `std`）；L 每学期按学科检查缺口；H 用户的优先安排（孩子的单元等）。
- 负责：CP；频率：每批新课、每月。关口：每课必须有 `std` 一行。

## 2. 事实与来源（实事求是）
- 标准：每个事实、数字、日期、引文和出处都可核实；有争议的地方说明有争议；不抄教材原文。
- 检查：L 由另一个 Codex 校对（用脚本重算数字，核对公式、单位和测验答案）；A 模拟中的数字用脚本重算；H 抽查历史、政治内容。
- 负责：CX／CP。关口：校对通过后才发布。

## 3. 文字（英文 + 中文）
- 标准：双语对等（每一处可见文字都有两种语言，意思相同）；中文用大陆用语和全角标点；英文适合 12–14 岁；不出现针对某个班级的说法（网站是公开的）。
- 检查：A 扫描没有 data-zh 的文字、禁用词（class／teacher／Canvas 等）、中文里的半角标点；L 翻译审查；H 用户阅读。
- 负责：CX／CP。关口：A 扫描无问题。
- 审查记录采用 MQM 式的错误分类（准确、通顺、术语、风格；轻微／严重／致命）。

## 4. 教学
- 标准：目标清楚；模拟和图像先行；有例题（美式题型 + 已知／求／解／答）；每节之后有随堂测试；列出常见误区；最后有带解析的测验；分难度。
- 检查：L 按 COMMON.md 检查结构；A 测验答案自检（每题恰好一个正确答案，每题都有解析）；H 请孩子试读。
- 负责：CX／CP／U。
- 借鉴别处的做法：按 Achieve OER 评价量表的 8 个维度给每课打分（课标对应、讲解、教学实用性、评价、互动、练习、深度学习、无障碍；每项 0–3 分，评到最小单元）；并像 PhET 一样，一课要经过目标年龄的学生（用户的孩子）边做边说的试用，才去掉“新课”标记。

## 5. 交互与功能
- 标准：每个控件都能用鼠标、触屏和键盘操作；没有 JS 错误；模拟的表现符合物理、数学规律；切换语言后状态不丢；朗读控件工作正常（手动翻页时停止、自动朗读、双击朗读、能停下来）。
- 检查：A 每页无头浏览器检查（JS 错误、坏图、未渲染的 TeX、390 px 宽度溢出）——`tools/qa/phone_sweep`、`hover_test`、媒体步骤；A 逐项点击的抓取（朗读文本抓取同时就是冒烟测试，“页面丢失”即失败）；A 朗读停止测试（`.labtmp/test_stop.mjs`：浏览器声音和录音两种情况，停止按钮、Esc、再次双击）；L 新页面的代码审查；H 用户亲手试用。
- 负责：CP／CX。关口：每个新页面或改过的页面检查无问题。

## 6. 审美（美育，画面安静）
- 标准：版面安静、不杂乱；字体、颜色统一；美通过例子、图片、声音体现——“画龙点睛”，不设单独的“美在哪里”卡片；次要内容折叠。
- 检查：A 每个新页面在 1300 px 和 390 px 宽度下截图（`vshot`）；L 对照网站风格审查截图；H 用户判断。
- 负责：CP／U。

## 7. 媒体与版权
- 标准：只用真实、核实过的媒体（Wikimedia Commons 并署名，核实过的 YouTube／哔哩哔哩视频）；署名放在页面上，从不朗读；没有失效或被删的视频。
- 检查：A 每页图片加载检查；A 每月检查视频是否可用（YouTube oEmbed、哔哩哔哩接口）；L 新媒体的授权检查。
- 负责：CP。频率：每次发布 + 每月一次链接和视频检查。

## 8. 年龄适宜与价值观
- 标准：适合 11–14 岁；不用暴力作品，不涉及文化战争或党派争议；历史的黑暗面简短、平实地讲；人类命运共同体、人民史观是看问题的角度，不是口号；来源平衡。
- 检查：L 对历史、政治、文学页面做敏感性审查；H 用户。涉及武器等题材的课（如核裂变、核聚变），只讲到课本和百科的程度，不涉及任何制造细节，并有对应的和平利用内容。
- 负责：CX／CP／U。关口：新的人文页面须经 L 审查。

## 9. 无障碍与兼容
- 标准：可用键盘操作，焦点可见，对比度 ≥ 4.5:1，配色对色盲友好，动画可以停止，图片有替代文字；在 Edge、Chrome、Safari／iOS、Android 上都能用；加载快。
- 检查：A 每页 axe-core／对比度扫描；A 加载时间和体积预算；H 真机检查（iPhone、Android）。
- 自动扫描只能发现大约一半的无障碍问题（多数 WCAG 条款没有自动规则），所以新的交互类型要人工做键盘和读屏检查，作为关口的一部分。
- 负责：CP。频率：每个新页面 + 每季度全面扫描。

## 10. 朗读稿
- 标准：声音从不直接读页面文字。凡是含数字、单位、符号、公式、中文里的拉丁字母或英文里的汉字的句子，都要有朗读稿（`say`）：意思、用词和顺序完全不变，把所有内容写成读出来的样子——数字按意思读（年份逐位读，“两”和“二”，“二度”），单位按书写顺序读（二十公里每小时），日期和时间，负数（负、零下、南纬），化学式（H二O）和离子，符号，希腊字母，范围（六到八年级），保留句末标点以便停顿；图片署名和授权信息从不朗读；不用括号。多音字用 `tools/tts/polyfix.tsv` 为声音替换，不改页面。
- 检查：
  - 由 Codex 按 RULES_zh.md／RULES_en.md（附真实例子）撰写，再由另一次 Codex 审查；
  - A 校验脚本：没有残留的数字和符号，汉字覆盖率（中文）／单词或字母覆盖率（英文），没有漏掉内容；
  - A 数字检查（TP 提议）：`send` 里的每个数字，都必须以某种正确读法出现在 `say` 里；
  - A 基于规则的文本规范化只作交叉核对：它对某个数字的读法与 LLM 不同时，这句退回审查；
  - 语音识别检查和用户试听的反馈：每个读错的地方都变成一条规则、一个例子或一条 polyfix；
  - H 每批新稿在 `listen/say.html` 上抽查；过不了检查的句子由人工撰写。
- 页面文字改动后：重新抓取 → 导出 → 新句子入队（`queue_new.py`）→ 写稿 → 发布 → 录音。
- 负责：CX（撰写／审查）、CP（规则、校验、发布）、TP（数字检查、审查）、U（读法的决定）。
  关口：需要朗读稿的句子，在它的朗读稿检查通过并发布之前，不录音。

## 11. 朗读录音
- 标准：页面能读出的每一段文字（自动朗读、按钮、悬停／双击／长按）都有录音：有 Serena（MOSS 8B）就用 Serena，否则用 Edge 替代录音，浏览器声音只是最后的退路。读法正确（多音字、数字、单位、日期），语速自然，没有杂音，音量平稳。
- 一课的流程（一课一课来）：
  1. 重新抓取这一课的全部文字（含双击朗读的段落和测验的全部题目）；
  2. 覆盖核对（`.labtmp/audit_audio.mjs <课>`）：页面上每一段可朗读的文字都在朗读文本里；
  3. 为这一课的新句子写朗读稿、审查、校验、发布；
  4. 用 Edge 录这一课（`edge_record.py <语言> <语料> F:\labtmp_edge <课>`），当天就有声音；
  5. 8B Serena 录这一课，替换 Edge；
  6. 质量检查：覆盖核对结果为“无录音 0”；语音识别 + LLM 复查；
  7. 用户在试听页（`listen/lesson.html?id=<课>`）听，标出问题，问题改完再查；
  8. 在课程状态表里标为“完整”，汇报，然后下一课。
- 检查：
  - A **覆盖核对**：每页、中英文、全部可朗读文字对照朗读文本和 Serena／Edge 清单。“完整”只看这个结果。
  - 朗读稿：见第 10 节。
  - A + L **语音识别检查**（TP）：用 FunASR／Whisper 识别线上录音，与朗读稿对照，再由 LLM 判断（真读错还是识别误差）→ 重录清单；读错的地方补进 RULES_zh/en.md 和 polyfix.tsv。
  - A 录音程序内的语速、音高、音量和尾音检查（moss_engine.check）。
  - A 多音字读音检查：多音字模型（g2pW／g2pM）预测朗读稿中每个多音字应有的拼音，与语音识别结果的拼音比较（只看识别错字率会漏掉这类错误，而语音识别也会误报，所以还要 LLM 判断和人工试听）。
  - H 试听页（`listen/`）：抽样和每一种新出现的问题；新引擎、新声音或新规则上线，试听始终是放行关口（自动分数只是冒烟测试）。
- 负责：CP（朗读文本、朗读稿、Edge）、Colab 录音程序（8B）、TP（语音识别检查、独立质检）。关口：覆盖核对 + 校验 + 用户试听。

## 12. 隐私、安全、公开网站
- 标准：没有个人信息，没有班级或学校的指代，没有跟踪，任何仓库里都没有密钥（OpenAI 密钥、令牌）；公开的 GitHub issue 不含个人信息。
- 检查：A 每次推送前做密钥扫描（密钥、令牌、邮箱、电脑名）；A 禁用词扫描。
- 负责：CP。关口：扫描无问题才推送。

## 13. 技术健康与发布
- 标准：目录、文件、朗读文本三者一致；没有失效的站内链接；SEO 信息和站点地图是最新的；音频仓库低于 GitHub Pages 的 1 GB 限制（计划每个学科一个仓库）；发布可以回退。
- 检查：A 目录与朗读文本一致（每个上线的课都有朗读文本）；A 抓取结果对比（重新抓取后，某课某种语言的句子数变成 0 或明显减少，就不发布，先重抓）；A 链接检查；A 仓库体积检查；A 发布后线上检查（页面返回 200，音频清单可访问）。
- 负责：CP。关口：见下面的发布清单。

## 14. 运行维护
- Colab 会话（24 小时上限；恢复脚本 + Drive 环境备份）、计算单元、Edge 频率限制、TTS 电脑状态、磁盘空间（C 盘几乎满了；Edge 工作目录在固态硬盘 F:\labtmp_edge）。负责：CP，每次工作时检查。

## 15. 反馈闭环
- 用户、TTS 电脑或任何检查发现的问题 → 记录（tools/readaloud/qa/、GitHub issue）→ 修改 → 复查 → 变成规则或检查，不让它再出现。每月按类别汇总一次问题。

## 16. 一课更新之后（后续动作链）
1. **页面质检：** 校对（L）和页面检查（A：JS 错误、图片、TeX、390 px、无障碍扫描），截图（H／L）。
2. **发布：** 提交，目录／首页分类，SEO 信息和站点地图（`tools/seo/seo.ps1`），推送；线上检查（200）。
3. **朗读文本：** 重新抓取这一课（`readaloud_sync.ps1 -Only <课> -Force`，中英文，含双击文字）→ 与上一版对比句子数 → 导出。改动的句子得到新的编号，没改的句子保留原录音。
4. **朗读稿：** `queue_new.py` 把新句子（中、英）入队 → Codex 撰写 + 审查 → 校验 → 发布 `readaloud/say/<语言>.json`。
5. **Edge 替代录音：** 只录这一课的新句子（几分钟），当天页面就有声音。
6. **Serena（MOSS 8B）：** Colab 录音程序发现新的朗读文本或朗读稿版本，录新句子并推送这一课。
7. **覆盖核对**（`audit_audio.mjs <课>`）：每段可朗读文字都有录音；新录音的语音识别检查（TP）；出现新类型的文字时安排试听。
8. **清理：** 不再出现在任何朗读文本里的录音，列出清单，过一段宽限期后删除，使音频仓库保持小巧（Pages 1 GB 限制）。
9. **记录：** 改了什么、重录了什么，记入这一课的质检记录。
应有一个脚本（`tools/lesson_update.ps1`）对一组课执行第 3–7 步，避免遗漏。

## 发布清单（每次发布）
1. 新页面／改动页面的 A 页面检查（JS 错误、图片、TeX、390 px）。2. 校对通过（L）。3. 文字扫描（双语、禁用词、标点）。4. 密钥扫描。5. 目录与朗读文本一致；抓取结果没有变少。6. 发布后：线上检查，然后朗读文本导出 → 朗读稿 → Edge → 8B → 覆盖核对 → 试听。

## 参考过的做法
Achieve OER 评价量表（8 个维度，0–3 分）；PhET 的设计流程（学生访谈、课堂观察、无障碍研究）；NVIDIA Riva 语音合成评估（语音识别 CER/WER 只是冒烟测试，MOS/CMOS 试听才是真正的衡量）；关于 WER/UTMOS 局限和漏检读音错误的语音合成评估论文；g2pW／g2pM 多音字消歧；MQM 翻译质量分类；Deque 与 WCAG 关于自动无障碍测试覆盖面的研究。

## 请 TTS 电脑回答的问题
- 对各节的补充；哪些检查可以在你的电脑上做（语音识别、独立的音频质检、无障碍扫描？）。
- 阈值：语音识别检查的 CER、语速范围、音量范围。
- 你的独立检查多久做一次，结果发在哪里。
